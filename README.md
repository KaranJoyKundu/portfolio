# Portfolio — Karan Joy Kundu

Premium personal portfolio for **Karan Joy Kundu**, second-year Electronics and
Communication Engineering student at [KUET](https://www.kuet.ac.bd/), Khulna,
Bangladesh. Embedded systems · analog electronics · robotics · machine learning.

React 19 + TypeScript (strict) + Vite 8 · Tailwind CSS 4 with CSS-variable design
tokens · Motion · Lucide · Vitest · GitHub Pages.

## Quick start

```bash
npm install
npm run dev        # local dev server
npm run check      # typecheck + lint + tests + production build (the CI gate)
npm run preview    # serve the production build at /portfolio/
```

Requires Node 20+ (workflow uses 24).

## Scripts

| Script | What it does |
|---|---|
| `dev` | Vite dev server |
| `build` | `tsc -b` + Vite build + emits `dist/404.html` (GH Pages SPA shim) |
| `preview` | Serve `dist/` locally |
| `test` | Vitest once |
| `typecheck` / `lint` / `format` | Quality gates |
| `check` | typecheck → lint → test → build — must pass before deploy |

## Editing content

Everything lives in `src/content/`. Pages render only **verified** facts
(`contentStatus: "verified"`); placeholders exist only in development, and a CI
report (`content-placeholder-report.json`, generated by the tests) lists every
pending item.

### Add or edit a project

1. Copy any file in `src/content/projects/` (e.g. `lm393-battery-fuel-gauge.ts`).
2. Fill: `slug` (kebab-case, unique), `title`, `summary` (one factual sentence),
   `status` (`shipped | in-progress | concept` — **only as confirmed**), `tags`
   (`Embedded | Analog | Robotics | ML | Web`), `tech`, `order`, `featured`
   (exactly three featured, Bee first).
3. `year` and `links` (`github`/`demo` URLs): add **only real values** — the
   absence is handled gracefully (nothing fake is rendered).
4. Images: when you have real screenshots, replace the placeholder image block:
   `{ status: "verified", figures: [{ src, alt, width, height, caption? }] }` —
   dimensions are mandatory (no layout shift).
5. Case study: when written, replace `{ status: "placeholder" }` with the
   `verified` block (problem, constraints, decisions, challenges + fixes,
   results, what-I-would-improve, optional BOM/diagram).
6. Register it in `src/content/projects/index.ts`. Done — grid, filters,
   detail page, skill links, resume, and sitemap all update.

### Achievements

`src/content/achievements.ts` — add an item with `contentStatus: "verified"`,
`category` (`academic | chess | project`), `year`, and a real `source` URL.
Items without a source never render; the section **and its nav link stay
hidden** until at least one verified item exists.

### Timeline & lab notebook

`src/content/timeline.ts` (verified `{ period, title, body? }`) and
`src/content/lab-entries.ts` (verified `{ slug, title, ISO date, excerpt, tags }`).

### Site links & identity

Single source of truth: `src/content/site.config.ts` (name, email, GitHub,
LinkedIn, "currently building"). Change contact details only there.

## Design tokens

All in `src/styles/tokens.css`: color (dark default + `.light` overrides),
fonts (Space Grotesk display, IBM Plex Mono labels, system sans body),
radii, motion durations and easing. Tailwind utilities map onto these tokens
via `@theme inline` — never hardcode hex values in components.

**Contrast is enforced**: `src/tokens.test.ts` computes WCAG contrast for every
text/background pair in both themes and fails the build below AA.

**Motion contract**: ≤ 320 ms, opacity/transform only, static frames under
`prefers-reduced-motion`, waveform renders without JS animation.

## Framework decisions worth knowing

- Zod validates content at **build/CI time** (tests), keeping it out of the
  runtime bundle; invalid content still fails the build.
- Routes are code-split (`React.lazy`) except Home (kept eager for LCP).
- The GH Pages deep-link fallback is `dist/404.html`, generated by
  `scripts/emit-404.mjs` with the correct base path.

## Deployment (GitHub Pages)

1. Create the GitHub repo `KaranJoyKundu/portfolio`, push this project
   (`git remote add origin … && git push -u origin main`).
2. Repo **Settings → Pages → Source: GitHub Actions**.
3. The included workflow (`.github/workflows/deploy.yml`) runs `npm run check`,
   builds, and deploys on every push to `main`.
4. Live at `https://karanjoykundu.github.io/portfolio/`.

**Base path — single place:** `VITE_BASE` (default `/portfolio/`).
If the repo is ever renamed, update `VITE_BASE` in the workflow's two `env`
blocks; the app, og URLs, and `404.html` derive from it. Two static files also
contain the absolute domain: `public/sitemap.xml` and `public/robots.txt` (URLs
change only when the domain/repo changes).

### Adding a custom domain later

1. Buy the domain; in repo **Settings → Pages → Custom domain**, enter it
   (e.g. `karanjoykundu.com`).
2. DNS at your registrar:
   - **Apex** (`karanjoykundu.com`): four `A` records → `185.199.108.153`,
     `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
   - **www** (`www.karanjoykundu.com`): `CNAME` →
     `karanjoykundu.github.io`.
3. Add a `CNAME` file (containing the domain) in `public/` so it lands in
   `dist/`.
4. Update `site.siteUrl` in `site.config.ts`, the URLs in `sitemap.xml` /
   `robots.txt`, and set `VITE_BASE=/` in the workflow.
5. Enforce HTTPS in Pages settings (wait for certificate provisioning).
6. Remove the old `karanjoykundu.github.io` site/URLs to avoid duplicate content.

## Troubleshooting

| Symptom | Fix |
|---|---|
| 404 on deep links after deploy | Check the Pages source is *GitHub Actions* and the 404 shim exists (`npm run build` emits it) |
| Assets 404 under subpath | `VITE_BASE` in the workflow must match the actual subpath |
| Blank page / style flash of light theme | `index.html` inline theme script must stay before styles |
| Tests fail with missing token | Tokens are parsed from `src/styles/tokens.css` — keep the `:root` / `.light` blocks intact |
| Placeholder content visible in production | Should be impossible: loader hides placeholder bodies; if the report shows an item you want shipped as real content, supply the verified data |
